## 1. Context

This is Agent 2 in the BnBuddy SEO pipeline. The Research Agent (Agent 1) runs weekly and produces `pipelines/seo-content-pipeline/data/research-brief.json` — a prioritized list of cities and blog topics with supporting research data. The Content Agent consumes that brief and **writes copy** for one geo landing page or blog post per run.

The first research brief (2026-03-14) identified 6 target cities in the State of Mexico, with Valle de Bravo, Malinalco, and Metepec as this week's priorities. Three competitors were scanned (bnbhomemx.com, guestify.mx, otium.com.mx) — **none have city-specific landing pages**.

## 2. Design Decision: Copy Only, No HTML

### Why the Agent Writes Markdown, Not HTML

The Toluca landing page (`public/es/administracion-renta-vacacional-toluca/index.html`) is **1,002 lines of HTML** — WordPress export with Breakdance CSS classes, lazy-loading image markup, inline styles, SVG icons, sidebar widgets, footer navigation, and analytics scripts. The actual content is ~40 lines of text buried inside this.

Asking an LLM to reproduce this HTML structure while writing creative content is:
- **Wasteful** — 95% of tokens go to reproducing identical boilerplate
- **Fragile** — one broken `</div>`, one wrong CSS class = broken page
- **Unreviewable** — Alberto can't evaluate content quality through HTML noise

### The Split

```
Content Agent (AI)              Build Script (Node.js)
─────────────────               ──────────────────────
Writes: pipelines/seo-content-pipeline/content/          Reads: pipelines/seo-content-pipeline/content/*.md
  valle-de-bravo.md               + pipelines/seo-content-pipeline/page-template.html
  malinalco.md                  Writes: public/es/administracion-
  metepec.md                      renta-vacacional-[city]/index.html
                                
Creative writing,               Deterministic, testable,
research, SEO copy              never breaks the template
```

**Agent writes:** structured markdown with YAML frontmatter (content + metadata)
**Build script writes:** final HTML by injecting markdown content into the page template

### Tradeoffs

| Concern | Impact | Mitigation |
|---------|--------|------------|
| Need to write a build script | ~100 lines of Node.js (cheerio already in deps) | One-time effort; reusable for all pages |
| Template changes need script update | Rare — template is stable | Template extracted once; script maps sections by CSS selectors |
| Images can't be generated by agent | No images on first publish | See §5 — images handled separately |
| Two-step process | Content → build → review | Build script runs in post-processing (already a step) |

### Section Mapping (Markdown → HTML)

The build script maps these markdown sections to the Toluca page's HTML structure:

| Markdown Section | HTML Target |
|-----------------|-------------|
| Frontmatter `title` | `<title>`, `og:title`, `twitter:title` |
| Frontmatter `description` | `<meta name="description">`, `og:description`, `twitter:description` |
| Frontmatter `slug` | `<link rel="canonical">`, `og:url` |
| Frontmatter `ogImage` | `og:image`, `twitter:image` |
| Frontmatter `date` | `.ee-postmeta-date` span |
| Frontmatter `readingTime` | `twitter:data2` |
| H1 → `"Administración de Renta Vacacional en {city}"` (template prepends the phrase; `city` field provides only the city name) | `.bde-heading-338-102` |
| First paragraph (before first H2) | Intro paragraph in `.bde-rich-text-338-101` |
| `## ¿Por qué...` | First `<h2 class="wp-block-heading">` section |
| `## Lugares populares...` | Second H2 section (bold name + description pattern) |
| `## Eventos y tendencias...` | Third H2 section |
| `## ¿Cómo te ayuda...` | Fourth H2 section (bullet list) |
| `## Preguntas Frecuentes...` | Fifth H2 section (bold Q + `<br>` A pattern) |
| Final CTA paragraph | Last `<p>` in rich-text div |

### Blog Post Format

Blog posts use the same frontmatter but with `type: blog-post`:


### How Agents Find Their Work

No shared state file. Each agent looks at the filesystem:

| Agent | "What do I do?" | How it decides |
|-------|----------------|----------------|
| Research Agent | What cities to research | `ls public/es/administracion-renta-vacacional-*/` + `ls pipelines/seo-content-pipeline/content/` |
| Content Agent | What content to write | Reads `research-brief.json` → checks `contentPlan` → skips items where `pipelines/seo-content-pipeline/content/[slug].md` exists |
| Build Script | What pages to build | `ls pipelines/seo-content-pipeline/content/*.md` → builds any without corresponding HTML in `public/es/` |
| Monitor Agent | What pages to track | `ls public/es/administracion-renta-vacacional-*/` |

### Handoff Contract

**Research Agent → Content Agent:**
- Research Agent commits `pipelines/seo-content-pipeline/data/research-brief.json` with a `contentPlan` array
- Each `contentPlan` item has: `run` (order), `type` (geo-page/blog-post), `ref` (city slug or post slug)
- The `targetCities[].research` object provides pre-gathered data (landmarks, events, stats, keywords)
- Content Agent uses this data as a starting point but does its own `web_fetch` verification

**Content Agent → Build Script:**
- Content Agent commits `pipelines/seo-content-pipeline/content/[slug].md` files
- Build script reads these, injects into template, outputs final HTML
- Build script is deterministic — same input always produces same output

**Build Script → Monitor Agent:**
- Built pages land in `public/es/administracion-renta-vacacional-[slug]/`
- Monitor Agent scans these directories to know what to track

## 6. Build Script Specification

**File:** `scripts/build-geo-pages.js`
**Added to package.json:** `"build-geo-pages": "node scripts/build-geo-pages.js"`
**Dependencies:** `cheerio` (already installed), `gray-matter` (needs install for frontmatter parsing), or hand-parse YAML frontmatter

### What It Does

1. Read `pipelines/seo-content-pipeline/page-template.html` (extracted from Toluca page with placeholder markers)
2. For each `pipelines/seo-content-pipeline/content/*.md`:
   a. Parse frontmatter (metadata) and body (markdown content)
   b. Convert markdown → HTML (headings, bold, lists, links, paragraphs)
   c. Inject metadata into `<head>` (title, description, canonical, OG, twitter)
   d. Inject content HTML into the `.bde-rich-text-338-101` container
   e. Inject `{{CITY_NAME}}` — the template renders the full H1 as "Administración de Renta Vacacional en {city name}"
   f. Write to `public/es/administracion-renta-vacacional-[slug]/index.html`
3. Report what was built

### Template Extraction

The page template is the Toluca page with content replaced by placeholder markers:

```html
<!-- In .bde-rich-text-338-101 -->
{{CONTENT}}

<!-- In .bde-heading-338-102 — template prepends the phrase, only supply the city name -->
{{CITY_NAME}}
<!-- Renders as: "Administración de Renta Vacacional en {city name}" -->

<!-- In <head> -->
<title>{{META_TITLE}}</title>
<meta name="description" content="{{META_DESCRIPTION}}">
<!-- etc. -->
```

This is a one-time extraction task (Phase 0).

## 9. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| AI content flagged by Google | Deindexed | Agent researches real local data; Alberto reviews before publish; unique per city |
| Build script breaks template | Broken pages | Template is static; script is deterministic and testable; Alberto reviews HTML output |
| Content Agent hallucinates landmarks | Bad content, credibility hit | Agent must `web_fetch` verify every landmark and event; instruction file is explicit about this |
| Markdown format drift | Build script can't parse | Strict format in instructions + example file; build script validates frontmatter |
| No images on new pages | Lower engagement | Pages are text-first SEO content; images added in Phase 2 |
| Research brief missing on Content Agent run | Wasted run | Agent checks for brief first, exits gracefully if missing |
